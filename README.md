# check_holidays

**모니모아(가계부 앱)가 읽어 가는 대한민국 공휴일 보충 데이터 한 파일.**

앱 스토어 업데이트 없이 새 공휴일(임시공휴일·선거일 등)을 사용자에게 내려보내기 위한
정적 JSON 호스팅입니다. 서버도, API도, 빌드도 없습니다 — `holidays.json` 하나가 전부입니다.

```
https://raw.githubusercontent.com/gilomonlabs/check_holidays/main/holidays.json
```

---

## 왜 이게 있나

가계부 달력이 공휴일을 빨갛게 칠하려면 공휴일 날짜를 알아야 합니다. 방법이 두 가지였습니다.

**(A) 공공데이터포털 특일정보 API를 앱에서 직접 호출** — 채택하지 않았습니다.

- 설날·추석·석가탄신일이 **음력**이라, 한국천문연구원이 수기로 입력한 **미래 약 1년치**만 제공됩니다.
  달력 앱은 2030년 12월도 넘겨볼 수 있어야 하는데 그 달이 비어 버립니다.
- API 키가 필요하고, 앱을 켤 때마다 외부에 접속해야 합니다.
  모니모아는 "가계부 데이터를 밖으로 보내지 않는다"를 원칙으로 하는데 결이 맞지 않았습니다.

**(B) 앱에 내장 + 필요할 때만 이 파일로 보충** — 이쪽을 택했습니다.

- 고정 양력 공휴일 8종(1/1·3/1·5/5·6/6·8/15·10/3·10/9·12/25)은 **앱이 코드로 계산**합니다. 연도 제한이 없습니다.
- 음력·대체공휴일은 **2025~2030년치를 앱에 내장**했습니다. 인터넷 없이 동작합니다.
- 그 사이에 **임시공휴일이 새로 지정되거나 선거일이 잡히면** — 스토어 심사를 기다릴 수 없습니다.
  그때 이 저장소의 `holidays.json`만 고치면 사용자 앱에 반영됩니다. **이 파일의 존재 이유입니다.**

## 어떤 API를 쓰나

**앱이 읽어 갈 때는 아무 API도 쓰지 않습니다.** GitHub이 정적 파일을 raw로 서빙하고,
앱은 평범한 HTTPS GET 한 번을 보낼 뿐입니다. 인증도 키도 없습니다.

**데이터를 채울 때**는 GitHub Actions가 하루 한 번 아래를 읽습니다:

| | |
|---|---|
| 출처 | 구글 캘린더 **'대한민국의 휴일'** ICS (공개, **API 키 불필요**) |
| 커버 | 2021~2031년 (앱 내장은 2030까지라 그 너머를 채워 준다) |
| 거르는 것 | `기념일`(식목일·어버이날 등)·고정 양력 8종·노동절 |
| 반영 | **추가만.** 삭제는 사람이 판단 (아래 참고) |

공공데이터포털 특일정보(`15012690`)는 **서비스 키가 필요해서** 쓰지 않습니다.
초기 2025~2030 값은 그 데이터를 사람이 확인해 넣은 것이고, 지금은 위 자동 수집이 이어받습니다.

### 왜 삭제는 안 하나

출처가 **미래 연도의 대체공휴일·선거일을 빠뜨립니다.** 실측 예:

- `2030-05-06` 어린이날 대체공휴일(월요일) — 출처에 없음
- `2028-04-12` 국회의원선거일(수요일) — 출처에 없음
- `2030` 설 연휴를 `02-04` 하루만 앎 (실제 2/2~2/5)

주말이라 생략한 것도 아니어서, "출처에 없으니 지운다"로 가면 멀쩡한 휴일이 사라집니다.
그래서 **추가만** 하고, 잘못 들어간 날짜를 빼는 것은 사람이 손으로 합니다.

## 파일 형식

```json
{
  "version": 1,
  "updated": "2026-06-05",
  "note": "메모(앱은 무시)",
  "dates": ["2026-08-17", "2027-05-13"]
}
```

| 키 | 필수 | 설명 |
|---|---|---|
| `version` | **예** | 정수. 앱이 가진 값보다 **크면** 업데이트로 인식. 값을 바꿨으면 **반드시 +1** |
| `dates` | **예** | `YYYY-MM-DD` 문자열 배열. 음력·대체·선거·임시공휴일만 |
| `updated` | 아니오 | 사람이 보려고 적는 날짜. 앱은 읽지 않음 |
| `note` | 아니오 | 메모. 앱은 읽지 않음 |

**`dates`에 넣지 말 것** — 고정 양력 8종(신정·삼일절·어린이날·현충일·광복절·개천절·한글날·성탄절).
앱이 코드로 계산하므로 중복입니다.

## 어떻게 동작하나

```
앱 시작
  └─ 마지막 확인으로부터 12시간 지났나?
       ├─ 아니오 → 아무것도 안 함 (접속 0회)
       └─ 예 → 이 URL에 GET (타임아웃 8초)
              ├─ 실패·오프라인·404 → 조용히 무시, 내장 데이터로 계속 동작
              └─ 성공 → version 비교
                     └─ 서버 version > 적용된 version
                          └─ 설정 탭에 빨강 점 ● (자동 적용은 안 함)

사용자가 설정 → 공휴일 데이터 → [적용]
  └─ dates를 기기에 저장 → 달력 즉시 반영 → 이후 오프라인에서도 유지
```

핵심 두 가지:

- **자동으로 적용되지 않습니다.** 앱은 "새 게 있다"고 점만 찍고, 사용자가 [적용]을 눌러야 반영됩니다.
- **끊겨도 앱은 멀쩡합니다.** 접속 실패는 전부 조용히 무시되고 내장 데이터로 동작합니다.

## 갱신 방법

### 자동 (평소)

`.github/workflows/auto-update.yml` 이 **매일 06:17 KST** 에 돕니다.
새 공휴일이 생기면 `dates` 에 넣고 `version` 을 +1 해서 스스로 커밋합니다.
바뀐 게 없으면 아무것도 하지 않습니다. Public 저장소라 **Actions 는 무료**입니다.

즉 임시공휴일이 발표되면 **손대지 않아도 며칠 안에 반영**됩니다.
당장 돌리고 싶으면 Actions 탭 → `auto-update` → **Run workflow**.

### 손으로 (자동이 못 잡는 것)

출처가 모르는 휴일(미래 선거일 등)이나, 잘못 들어간 날짜를 **뺄 때**는 직접 고칩니다.

예: 2027년 10월 15일이 임시공휴일로 지정됐다면

1. `holidays.json`의 `dates`에 `"2027-10-15"` 추가
2. **`version`을 +1** (1 → 2)
3. `updated`를 오늘 날짜로 (선택)
4. 커밋 & push

끝입니다. 사용자 앱은 다음 실행(12시간 throttle 통과) 때 점을 띄웁니다.

### 삭제·수정도 됩니다

`version`만 올리면 `dates` **전체가 통째로 교체**됩니다. 잘못 넣은 날짜를 빼고 version을 올리면
[적용]한 사용자에게서 그 날짜가 사라집니다.

**단, 앱에 내장된 2025~2030 날짜는 이 파일로 지울 수 없습니다.** 판정이 `내장 OR 다운로드`라
이 파일은 **더하기만** 할 수 있습니다. 내장 날짜가 틀렸다면 앱 업데이트가 필요합니다.

---

## 함정

- **`version`을 안 올리면 아무 일도 안 일어납니다.** `dates`만 고치고 push하면 사용자는 영원히 못 받습니다. 가장 흔한 실수입니다.
- **`version`을 낮추면 무시됩니다.** 비교가 `>`라서, 되돌리려면 **더 높은 번호**로 올려야 합니다.
- **형식이 깨지면 조용히 무시됩니다.** JSON 파싱 실패·`version`이 정수가 아님·`dates`가 배열이 아님 → 앱은 그냥 못 본 척합니다. 오류 화면이 없으니 push 전에 확인하세요 (CI가 자동으로 검사합니다).
- **`YYYY-MM-DD`가 아닌 문자열은 조용히 버려집니다.** `2026-8-17`(0 없음)은 통째로 무시됩니다.
- **반영은 최대 12시간 + 사용자의 [적용] 클릭이 걸립니다.** 즉시 반영되지 않습니다.

## 개인정보

앱이 이 URL에 보내는 것은 **평범한 GET 요청 하나(약 1KB 응답)** 뿐입니다.
거래 내역·계정·기기 식별자 등 어떤 개인정보도 전송하지 않습니다. 읽기 전용입니다.

## 이 저장소를 지워도 되나

**지워도 앱은 안 죽습니다.** 요청이 실패하면 조용히 무시되고 내장 데이터로 계속 동작하며,
이미 [적용]한 사용자의 날짜는 기기에 캐시돼 그대로 남습니다.

다만 지우는 순간 **스토어 업데이트 없이 공휴일을 고칠 수단이 사라집니다.**
정리하려면 순서가 있습니다:

1. 앱의 `manifestUrl`을 `''`로 되돌리고 배포 (12시간마다의 불필요한 접속 제거)
2. 그 버전이 충분히 퍼진 뒤 저장소 삭제

반대로 이 저장소는 **비워두면 안 됩니다.** 파일이 없으면 404 → 앱은 조용히 무시할 뿐이라
문제는 안 생기지만, 그럴 거면 `manifestUrl`을 비워 두는 편이 접속을 아낍니다.
