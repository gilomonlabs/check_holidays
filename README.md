# check_holidays

**모니모아(가계부 앱)가 읽어 가는 대한민국 공휴일 보충 데이터 한 파일.**

앱 스토어 업데이트 없이 새 공휴일(임시공휴일·선거일 등)을 사용자에게 내려보내기 위한
정적 JSON 호스팅입니다. 서버도, API도, 빌드도 없습니다 — `holidays.json` 하나가 전부입니다.

```
https://raw.githubusercontent.com/gilomonlabs/check_holidays/main/holidays.json
```

---

## 왜 이게 있나

가계부 달력이 공휴일을 빨갛게 칠하려면 공휴일 날짜를 알아야 합니다. 방법이 두 가지였습니다.

**(A) 공공데이터포털 특일정보 API를 앱에서 직접 호출** — 채택하지 않았습니다.

- 설날·추석·석가탄신일이 **음력**이라, 한국천문연구원이 수기로 입력한 **미래 약 1년치**만 제공됩니다.
  달력 앱은 2030년 12월도 넘겨볼 수 있어야 하는데 그 달이 비어 버립니다.
- API 키가 필요하고, 앱을 켤 때마다 외부에 접속해야 합니다.
  모니모아는 "가계부 데이터를 밖으로 보내지 않는다"를 원칙으로 하는데 결이 맞지 않았습니다.

**(B) 앱에 내장 + 필요할 때만 이 파일로 보충** — 이쪽을 택했습니다.

- 고정 양력 공휴일 8종(1/1·3/1·5/5·6/6·8/15·10/3·10/9·12/25)은 **앱이 코드로 계산**합니다. 연도 제한이 없습니다.
  - 2026년 법 개정으로 공휴일이 된 **노동절(5/1)·제헌절(7/17)** 은 vc74 이후 앱도 계산하지만, 그 전 빌드는
    모르므로 이 파일의 `dates` 에도 연도별로 실어 둡니다(출처가 2026년부터 '공휴일'로 표시해 자동 수집됨).
- 음력·대체공휴일은 **2025~2030년치를 앱에 내장**했습니다. 인터넷 없이 동작합니다.
- 그 사이에 **임시공휴일이 새로 지정되거나 선거일이 잡히면** — 스토어 심사를 기다릴 수 없습니다.
  그때 이 저장소의 `holidays.json`만 고치면 사용자 앱에 반영됩니다. **이 파일의 존재 이유입니다.**

## 정부 API 켜기 (권장 — 확실한 정보)

구글 캘린더는 공식 출처가 아니라서, 임시공휴일·대체공휴일이 지정됐는데 구글이 늦으면 앱 달력이 평일로 남을 수 있습니다.
공공데이터포털의 **한국천문연구원 특일정보**(관공서 공휴일의 원본)를 켜면 **올해·내년은 정부 데이터가 정답**이 되고
구글은 그 너머 연도 보충용으로만 씁니다. 키는 무료이고 자동 승인되지만, 저장소 주인만 받을 수 있습니다.

1. https://www.data.go.kr 로그인 → 검색 **"특일 정보"** → **한국천문연구원_특일 정보** → **활용신청**(개발계정, 즉시 승인).
2. 마이페이지 → 활용신청 현황 → 그 항목 → **일반 인증키(Decoding)** 복사. ★Encoding 키가 아니라 **Decoding** 키.
3. 이 저장소 → Settings → Secrets and variables → Actions → **New repository secret** → 이름 `DATA_GO_KR_KEY`, 값에 붙여넣기.
4. Actions 탭 → `auto-update` → Run workflow. 로그 첫 줄이 `정부 특일정보: N개, 온전한 해 [2026, 2027]` 이면 켜진 것입니다.
   `STATUS.md` 첫 줄에도 "정부 특일정보(정답): 2026, 2027" 로 나옵니다.

켜진 뒤의 규칙(`update_holidays.py` 상단 주석과 같음):

- 정부가 한 해를 온전히 돌려주면(12개 이상) 그 해는 **정부에 있는 날은 즉시 추가**, **정부에 없는 날은 3일 연속 없으면 취소**(`removed`).
- 그 해에는 구글이 더하는 날을 받지 않습니다(정부가 모르는 날을 넣었다 빼는 왕복 방지).
- 정부가 아직 모르는 해(보통 내후년 이후)는 아래 구글 규칙대로 갑니다.
- 키가 잘못되거나 한도를 넘으면 이슈가 열리고, 그동안은 구글만 씁니다.

## 어떤 API를 쓰나

**앱이 읽어 갈 때는 아무 API도 쓰지 않습니다.** GitHub이 정적 파일을 raw로 서빙하고,
앱은 평범한 HTTPS GET 한 번을 보낼 뿐입니다. 인증도 키도 없습니다.

**데이터를 채울 때**는 GitHub Actions가 하루 한 번 아래를 읽습니다:

| | |
|---|---|
| 출처 | 정부 특일정보 API(정답, 키 필요 — 위 '정부 API 켜기') + 구글 캘린더 **'대한민국의 휴일'** ICS (보충, 키 불필요) |
| 커버 | 2021~2031년 (앱 내장은 2030까지라 그 너머를 채워 준다) |
| 거르는 것 | `기념일`(식목일·어버이날 등)·고정 양력 8종 |
| 반영 | 추가는 자동. 삭제는 **출처가 알던 날을 7일 이상 거둬들였을 때만** 자동(아래 참고) |

공공데이터포털 특일정보(`15012690`)는 서비스 키가 필요해 처음엔 쓰지 않았고, 초기 2025~2030 값은 그 데이터를
사람이 확인해 넣은 것입니다. 지금은 키를 secret 에 넣으면 정부 데이터가 올해·내년의 정답이 됩니다(위 절).

### 삭제는 어떻게 하나

출처가 **미래 연도의 대체공휴일·선거일을 빠뜨립니다.** 실측 예:

- `2030-05-06` 어린이날 대체공휴일(월요일) — 출처에 없음
- `2028-04-12` 국회의원선거일(수요일) — 출처에 없음
- `2030` 설 연휴를 `02-04` 하루만 앎 (실제 2/2~2/5)

주말이라 생략한 것도 아니어서, "출처에 없으니 지운다"로 가면 멀쩡한 휴일이 사라집니다.
그래서 "출처에 없다"와 "출처가 **알다가 거둬들였다**"를 가릅니다(`source_seen.json` 에 출처가
언제 무엇을 알았는지 기록):

- 출처가 **한 번도 몰랐던** 날짜(사람이 넣은 것) → 절대 안 지운다. `STATUS.md` 에 목록만 보여 준다.
- 출처가 **알고 있다가 7일 이상 계속 안 보이는** 날짜(법 개정으로 폐지, 대체공휴일 날짜 이동) →
  `removed` 로 옮기고 `version` +1. 출처에 다시 나타나면 되살린다.
- 한 번에 **4개 이상** 거둬들여지면 출처 장애·형식 변경일 수 있어 손대지 않고 **이슈**를 연다.

## 파일 형식

```json
{
  "version": 1,
  "updated": "2026-06-05",
  "note": "메모(앱은 무시)",
  "dates": ["2026-08-17", "2027-05-13"]
}
```

| 키 | 필수 | 설명 |
|---|---|---|
| `version` | **예** | 정수. 앱이 가진 값보다 **크면** 업데이트로 인식. 값을 바꿨으면 **반드시 +1** |
| `dates` | **예** | **더할** 날짜. `YYYY-MM-DD` 배열. 음력·대체·선거·임시공휴일만 |
| `removed` | 아니오 | **뺄** 날짜. 앱 내장에 잘못 들어갔거나 법이 바뀌어 공휴일이 아니게 된 날 |
| `updated` | 아니오 | 사람이 보려고 적는 날짜. 앱은 읽지 않음 |
| `note` | 아니오 | 메모. 앱은 읽지 않음 |

`removed` 는 **`dates` 보다, 그리고 앱 내장·고정 양력보다 우선**합니다. 같은 날짜를
`dates` 와 `removed` 에 같이 넣으면 뜻이 모순이라 CI 가 막습니다.

**`dates`에 넣지 말 것** — 고정 양력 8종(신정·삼일절·어린이날·현충일·광복절·개천절·한글날·성탄절).
앱이 코드로 계산하므로 중복입니다.

## 어떻게 동작하나

```
사용자가 달력을 연다
  └─ 달력은 기존 데이터로 **즉시** 그려진다 (기다리지 않는다)
      └─ 뒤에서: 마지막 확인으로부터 7일 지났나?
           ├─ 아니오 → 아무것도 안 함 (접속 0회)
           └─ 예 → 이 URL에 GET (타임아웃 8초)
                  ├─ 실패·오프라인·404 → 조용히 무시, 기존 데이터 그대로
                  └─ 성공 → version 비교
                         └─ 서버 version > 적용된 version
                              └─ **바로 적용** → 달력이 저절로 다시 그려짐
                                 (기기에 캐시 → 이후 오프라인에서도 유지)
```

핵심 세 가지:

- **달력을 열 때만 확인합니다.** 공휴일이 쓰이는 곳이 달력뿐이라, 앱을 켤 때마다 볼 이유가 없습니다. 달력을 안 여는 사용자는 접속 0회입니다.
- **자동으로 적용됩니다.** 공휴일은 개인 데이터가 아니라 공개된 사실이라 물어보지 않습니다. 예전엔 설정에 빨강 점만 찍어서, 그 점을 못 본 사용자의 달력은 계속 틀린 채로 남았습니다.
- **화면을 막지 않습니다.** 달력은 기존 데이터로 즉시 그려지고, 새 날짜가 도착하면 그때 다시 그려집니다. 인터넷이 없으면 아무 일도 안 일어납니다.

## 갱신 방법

### 자동 (평소)

`.github/workflows/auto-update.yml` 이 **매일 06:17 KST** 에 돕니다.
새 공휴일이 생기면 `dates` 에 넣고 `version` 을 +1 해서 스스로 커밋합니다.
바뀐 게 없으면 아무것도 하지 않습니다. Public 저장소라 **Actions 는 무료**입니다.

★GitHub 은 공개 저장소에 **60일간 커밋이 없으면 schedule 워크플로를 자동으로 꺼 버립니다**(매일 돌아도 활동으로 안 칩니다).
스냅샷(`source_seen.json`·`STATUS.md`)이 7일마다 커밋되므로 평소엔 걸리지 않고, 그래도 45일 넘게 커밋이 없으면
`.github/last-run` 만 갱신해 커밋합니다(`holidays.json` 은 안 건드림 → 앱엔 영향 0). 그래도 꺼졌다면 Actions 탭에서 **Enable workflow** 한 번.

즉 임시공휴일이 발표되면 **손대지 않아도 며칠 안에 반영**됩니다.
당장 돌리고 싶으면 Actions 탭 → `auto-update` → **Run workflow**.

### 비교 결과 보기

`STATUS.md` 가 매주(또는 변화가 있을 때) 갱신됩니다 — 마지막 확인 날짜, 출처와 다른 날짜(사람이 넣은 것),
자동으로 취소한 날짜, 사람 확인이 필요한 날짜. 자동으로 취소·복구했거나 사람 확인이 필요하면 **이슈**가 열립니다
(저장소 소유자에게 메일이 갑니다).

### 손으로 (자동이 못 잡는 것)

출처가 모르는 휴일(미래 선거일 등)이나, 출처가 거둬들이지 않았는데 빼야 하는 날짜는 직접 고칩니다.

예: 2027년 10월 15일이 임시공휴일로 지정됐다면

1. `holidays.json`의 `dates`에 `"2027-10-15"` 추가
2. **`version`을 +1** (1 → 2)
3. `updated`를 오늘 날짜로 (선택)
4. 커밋 & push

끝입니다. 사용자가 다음에 달력을 열 때(마지막 확인으로부터 7일이 지났으면) 저절로 반영됩니다.

### 지우려면 — `removed` 에 넣으세요

`dates` 에서 빼는 것만으로는 **앱 내장 날짜를 못 지웁니다.** 판정이
`(고정 양력 ∪ 내장 ∪ dates) − removed` 라서, 내장에 들어 있는 날은 `removed` 로만 취소됩니다.

```json
{ "version": 3, "dates": [...], "removed": ["2028-10-05"] }
```

`dates` 에서 빼는 것으로 충분한 경우는 **이 파일로만 들어온 날짜**(내장에 없던 것)뿐입니다.
헷갈리면 그냥 `removed` 에 넣으세요 — 둘 다 커버합니다.

### 왜 "출처에 없으면 자동 삭제"를 안 하나

단순 동기화가 자연스러워 보이지만, **그렇게 하면 진짜 휴일이 지워집니다.** 실측:

| 출처에 없는 날 | 실제로는 |
|---|---|
| `2030-05-06` | 어린이날 5/5가 **일요일** → 대체공휴일 |
| `2029-05-07` | 어린이날 5/5가 **토요일** → 대체공휴일 |
| `2030-02-05` | 설날 2/3이 **일요일** → 대체공휴일 |
| `2028-04-12` | 국회의원선거일(수요일) |

게다가 누락이 "먼 미래일수록 심함" 같은 규칙도 아닙니다 — 출처의 대체공휴일 수가
2027년 7개, 2028년 0개, 2030년 0개로 들쭉날쭉해서 신뢰 경계를 그을 수가 없습니다.

그래서 자동 삭제는 **출처가 알던 날을 거둬들인 경우**로만 좁힙니다(위 "삭제는 어떻게 하나").
사람이 `removed` 에 넣은 날짜는 자동 수집이 다시 밀어넣지 않습니다(자동으로 취소한 날짜만 출처가
되돌리면 따라 되살립니다).

## 함정

- **`version`을 안 올리면 아무 일도 안 일어납니다.** `dates`만 고치고 push하면 사용자는 영원히 못 받습니다. 가장 흔한 실수입니다.
- **`version`을 낮추면 무시됩니다.** 비교가 `>`라서, 되돌리려면 **더 높은 번호**로 올려야 합니다.
- **형식이 깨지면 조용히 무시됩니다.** JSON 파싱 실패·`version`이 정수가 아님·`dates`가 배열이 아님 → 앱은 그냥 못 본 척합니다. 오류 화면이 없으니 push 전에 확인하세요 (CI가 자동으로 검사합니다).
- **`YYYY-MM-DD`가 아닌 문자열은 조용히 버려집니다.** `2026-8-17`(0 없음)은 통째로 무시됩니다.
- **`removed` 와 `dates` 에 같은 날짜를 넣으면** 뜻이 모순이라 CI가 막습니다.
- **반영에 최대 7일이 걸립니다.** push 즉시가 아닙니다 — 사용자가 달력을 열어야 하고, 마지막 확인으로부터 7일이 지나야 합니다. 급하면 앱 설정의 [지금 확인]이 throttle을 무시합니다.

## 개인정보

앱이 이 URL에 보내는 것은 **평범한 GET 요청 하나(약 1KB 응답)** 뿐이고,
그것도 **달력을 열 때 7일에 한 번**입니다. 거래 내역·계정·기기 식별자 등
어떤 개인정보도 전송하지 않습니다. 읽기 전용이고, 인증도 쿠키도 없습니다.

---

## 이 저장소를 지워도 되나

**지워도 앱은 안 죽습니다.** 요청이 실패하면 조용히 무시되고 내장 데이터로 계속 동작하며,
이미 받아 둔 날짜는 기기에 캐시돼 그대로 남습니다.

다만 지우는 순간 **스토어 업데이트 없이 공휴일을 고칠 수단이 사라집니다.**
정리하려면 순서가 있습니다:

1. 앱의 `manifestUrl`을 `''`로 되돌리고 배포 (불필요한 접속 제거)
2. 그 버전이 충분히 퍼진 뒤 저장소 삭제

반대로 이 저장소는 **비워두면 안 됩니다.** 파일이 없으면 404 → 앱은 조용히 무시할 뿐이라
문제는 안 생기지만, 그럴 거면 `manifestUrl`을 비워 두는 편이 접속을 아낍니다.
